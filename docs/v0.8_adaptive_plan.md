# Version 0.8 pre-registration: does local recalibration help at a new site?

**Status: AWAITING APPROVAL. Not executed. DRIAMS-C has not been downloaded, extracted, partitioned or
looked at.** Written 2026-09-24, after Version 0.7 was recorded and made immutable (run commit `8878bfd`,
results commit `64c6c75`, log SHA-256 `e97480ab…c6c8a048a`, 84 data rows).

This document is the protocol. Once the project owner approves it, it is committed **before** any Version 0.8
code exists, and nothing in it may change afterwards. The three decisions Version 0.7 left open are resolved
below with the evidence that resolved them; the decision table for approval is at the end.

State of the reserved data at the time of writing: not downloaded, not extracted, absent from every split,
0 rows in the built dataset. `config.yaml` → `reservation.driams_c` holds the partition (70 / 30, seed 42),
and `tests/test_utils.py::test_reserved_sites_are_not_used_by_any_version_that_reserved_them` refuses any
configuration that spends it.

## 1. The question, and the honest framing

The specification asks for adaptive retraining: new site data arrives, the model is adapted on approved
labelled samples, and old and new are compared. Version 0.8 tests exactly one pre-specified adaptation
strategy against a pre-specified baseline on a protected evaluation set. It is **not** a search for a
strategy that improves the result.

**Version 0.7 did not demonstrate a generalisation gap**, and this protocol does not assume one. Its
intervals were 0.128–0.182 wide, so it neither showed nor excluded a clinically relevant drop. Designing
Version 0.8 around "recover the lost performance" would therefore be designing around something that was
never established. What Version 0.7 *did* measure precisely is a **calibration-in-the-small defect**, and
that is what Version 0.8 addresses.

A null result is an expected and publishable outcome. It is reported with the same prominence as a positive
one, and section 9 fixes what each outcome means before any number exists.

## 2. What Version 0.7 evidence actually says about where the headroom is

Recorded in `results/metrics/v0.7/ecoli_ciprofloxacin/test_metrics.csv` and `zone_transfer.csv`.

| Site / part | AUROC | Brier | no-skill Brier | Calib. slope | Calib. intercept | Zone NPV | Covered |
|---|---|---|---|---|---|---|---|
| `random` (development) | 0.751 | 0.144 | – | – | – | 0.955 | 25.8 % |
| A 2018 (`temporal`) | 0.728 | 0.141 | 0.172 | 0.982 | **−0.270** | **0.893** | 253 / 1,233 |
| DRIAMS-B (saved model) | 0.809 | 0.133 | 0.203 | 1.019 | −0.077 | 0.922 | 51 / 213 |
| DRIAMS-D (saved model) | 0.704 | 0.134 | 0.156 | 0.972 | **−0.379** | 0.963 | 298 / 1,938 |

Three facts follow, and together they determine the design:

1. **The calibration slope is already near-perfect everywhere** (0.955–1.040). There is no slope defect to
   fix. Any claim that "calibration is poor" would be wrong.
2. **The intercept is not.** It is −0.27 at the later year and −0.38 at DRIAMS-D: the model systematically
   over-predicts resistance at both. An intercept shift is a **one-parameter** defect, and the matched
   intervention is a one-parameter correction that needs very little local data.
3. **The confidence zone misses its target in the later year** (0.893, interval wholly below 0.95) and is
   uninformative at B (51 covered spectra). D is the only informative positive.

## 3. Decision 1 — the primary endpoint

**Resolved: a calibration-sensitive endpoint, not AUROC. The primary endpoint is the Brier score.**

The reason is not that AUROC is harder to improve. It is that **AUROC cannot respond to the intervention at
all.** Recalibration is a monotone map of the probabilities, so it preserves every pairwise ordering and
therefore leaves AUROC exactly unchanged. This was verified on the recorded Version 0.7 DRIAMS-D
probabilities (1,938 spectra), applying five different Platt recalibrations:

| Recalibration | AUROC | Brier | Intercept | Zone NPV | Coverage |
|---|---|---|---|---|---|
| none (as scored in V0.7) | 0.704142 | 0.1335 | −0.379 | 0.963 | 0.154 |
| shift only, B = −0.5 | 0.704142 | 0.1290 | +0.121 | 0.905 | 0.336 |
| shift only, B = +0.5 | 0.704142 | 0.1539 | −0.879 | 0.991 | 0.058 |
| slope + shift, A = 0.8, B = −0.3 | 0.704142 | 0.1315 | −0.272 | 0.982 | 0.117 |
| strong, A = 1.3, B = +0.7 | 0.704142 | 0.1513 | −0.798 | 0.964 | 0.144 |

**All five AUROCs are bit-identical; the spread is 0.000e+00.** Choosing AUROC as the primary endpoint for a
recalibration arm would make the experiment mathematically guaranteed to be null — an empty experiment, not
a conservative one. Brier, the intercept, the zone NPV and its coverage all respond.

The same table exposes a trap that the endpoint definition must close. **Zone NPV alone is gameable:**
B = +0.5 reaches NPV 0.991 by shrinking coverage to 5.8 %, and B = −0.5 gives NPV 0.905 at 33.6 %. A "95 %
safe" zone covering almost nobody is worthless. So the zone is a **pair**, with a coverage floor, and it is
a co-primary with an explicit non-gaming constraint rather than the primary.

Brier is chosen as the single primary because it is a **strictly proper scoring rule**: it cannot be improved
by distorting the probabilities away from the truth, so unlike NPV it is not gameable in any direction. It is
also directly sensitive to the intercept defect of section 2, and it is the quantity a probability output is
supposed to be good at. Clinical relevance is carried by the co-primary zone pair, which is what a
laboratory would actually act on.

### Primary endpoint, defined

For the held-out part of DRIAMS-C with labels `y_i ∈ {0,1}` and predicted resistance probabilities `p_i`:

```
BS = (1/n) · Σ_{i=1..n} (p_i − y_i)²
```

The effect measure is the **paired difference**

```
Δ = BS(baseline) − BS(adapted)          Δ > 0 means adaptation is better
```

computed on the *same* held-out rows for both models, so the comparison is paired.

### Co-primary zone pair, defined

With an edge `e` (a probability cut) and `S = { i : p_i < e }`:

```
NPV(e)      = |{ i ∈ S : y_i = 0 }| / |S|          (undefined if |S| = 0)
Coverage(e) = |S| / n
```

The adapted zone is an improvement **only if both** hold on the held-out part:

```
NPV_adapted ≥ 0.95                                    (the Version 0.6 target, unchanged)
Coverage_adapted ≥ Coverage_baseline − 0.05           (the non-gaming floor)
```

The coverage floor is what stops an NPV gain bought by shrinking the zone. Both numbers are reported with
the count of covered spectra beside them, because Version 0.7 showed how misleading a zone number on 51
spectra is.

## 4. Decision 2 — the adaptation method

**Resolved: recalibration-only as primary, A + C refit as a pre-specified secondary, no search on C.** The
owner's proposed hierarchy is methodologically justified by the existing design, for the reasons below — but
one correction is needed, stated at the end of this section.

### Candidate 1 — recalibration-only (PRIMARY)

| | |
|---|---|
| **Parameters changed** | the two Platt parameters `(A, B)` of the sigmoid calibrator, and the zone edge `e` |
| **Data allowed to influence them** | the DRIAMS-C **adaptation part only** |
| **Frozen** | the entire LightGBM model — every tree, split and leaf; the preprocessing; the feature space; the decision threshold rule |
| **Leakage risk** | **Low.** Three parameters fitted on data disjoint from the held-out part by whole patient groups. The frozen model never sees a C row. |
| **Scientific interpretation** | tests whether the *probability scale* transfers, given that the *ranking* does. This is the intervention matched to the defect in section 2: one-parameter miscalibration, one-parameter correction. |
| **Improvement** | Δ Brier interval excludes 0 with Δ > 0, and the zone pair satisfies both conditions in section 3 |
| **Failure** | Δ Brier interval includes 0 (no demonstrated benefit) or excludes 0 with Δ < 0 (demonstrated harm) |

**Why primary:** it is the only arm whose intervention is matched to a defect the project actually measured;
it is the cheapest and the most realistic thing a receiving laboratory could do; and it changes nothing about
what the model has learned, so a positive result has an unambiguous interpretation.

### Candidate 2 — refit on A + C adaptation (SECONDARY)

| | |
|---|---|
| **Parameters changed** | all model parameters, refitted from scratch on A-train + C-adaptation with the **Version 0.4 winning setting unchanged**, plus its calibrator and zone edge |
| **Data allowed to influence them** | A training rows (as in Version 0.7's `external`) + the C adaptation part |
| **Frozen** | the hyperparameters, the preprocessing, the feature space, the threshold rule |
| **Leakage risk** | **Low–moderate.** No held-out C row is used, but this arm is the direct analogue of Version 0.7's `external_ab`, which showed no demonstrated benefit from pooling a small second site. |
| **Scientific interpretation** | tests whether local data helps by changing what is learned, not only how it is scaled |
| **Improvement / failure** | same rules as candidate 1, reported separately and **not** used to claim the primary result |

### Candidate 3 — unrestricted search on C (REJECTED)

Rejected, and the rejection is part of the pre-registration. A hyperparameter search on C would (a) let the
adaptation part choose the setting, so a gap could no longer be attributed to adaptation rather than to
search luck; (b) break comparability with Versions 0.4–0.7, all of which used one fixed setting; and (c)
multiply the ways to reach a favourable number. Version 0.7's design rests on a fixed recipe, and Version
0.8 keeps it.

### Candidate 4 — fine-tuning the saved booster (REJECTED for this version)

Continuing boosting from the saved model on C's adaptation part is a reasonable method, but it is **not
justified by the existing project methodology**: nothing in Versions 0.1–0.7 establishes a fine-tuning
procedure, an early-stopping rule for it, or how its result would be comparable with a fixed-setting refit.
Adding it now would mean inventing methodology inside a pre-registration. It is recorded as future work.

### The correction to the proposed hierarchy

The proposal is accepted with one change: **the secondary A + C refit must be pre-specified as
confirmatory-secondary, not exploratory**, and its result reported whichever way it falls. Version 0.7
already found no demonstrated benefit from pooling a small second site (`external_ab`, paired −0.016
[−0.034, +0.001]). If this arm were left informal, a negative result could be quietly dropped as
"exploratory". It is therefore fixed here with the same success and failure rules as the primary, and
Holm-adjusted alongside it (section 8).

## 5. Decision 3 — adaptation-set sizes

**Resolved: one pre-specified adaptation size for the primary endpoint. The learning curve is answered
inside the adaptation part by cross-validation, and never touches the held-out part.**

The problem with several sizes is precise: each size is a different model, so scoring *K* sizes on the
held-out part is *K* uses of the protected set. Picking the best size afterwards is selection on the
evaluation data, and even reporting all *K* honestly inflates the chance that one clears the bar.

Three designs were considered:

| Design | Held-out scorings | Defensible? |
|---|---|---|
| (a) one fixed size for the primary; curve by CV **inside** the adaptation part | 1 per arm | **yes — chosen** |
| (b) all *K* sizes scored on held-out, Holm-corrected | *K* per arm | yes, but wastes power and needs a larger held-out set |
| (c) size chosen on the adaptation part by internal CV, then one held-out scoring | 1 per arm | yes; equivalent to (a) but adds a selection step with no clear gain |

**Chosen: (a).**

- **Primary adaptation size: the entire adaptation part** (70 % of eligible C rows). Fixed, deterministic,
  no choice to make, and maximum power for the single primary comparison.
- **Learning curve (secondary, exploratory):** adaptation-set fractions **25 %, 50 %, 75 %, 100 %** of the
  adaptation part, evaluated by **5-fold patient-grouped cross-validation within the adaptation part only**,
  seed 42. Each fraction is a nested, deterministic subset drawn by `grouped_subsample` with seed 42, so
  smaller fractions are subsets of larger ones. The held-out part is **not** used, so this adds **zero**
  held-out scorings and cannot influence the primary.
- The curve answers "how little local data would have sufficed?" — which is what the specification's "small
  subset" is really asking — without spending the protected set on it.

**Adaptation data and final evaluation data are disjoint by construction and by assertion.** The held-out
30 % is used exactly once per final model, for the endpoints in section 3, and never to choose a size, a
method, an edge or a threshold.

## 6. Data

### 6.1 Cohort and eligibility — the gate before anything is fitted

DRIAMS-C (Canton Hospital Aarau, 01/2018–08/2018), archive `DRIAMS_C.tar.gz`, 12.43 GB, SHA-256
`77c8097eeb09e9c07397d94b5d888684ca5421d76e4567e1d67fdd75685b7867` as recorded in `config.yaml` and
confirmed against Dryad's file record on 2026-09-23.

In this order, and no further:

1. **Download** in a browser (Dryad's API refuses scripted downloads: `401 Unauthorized, must have current
   bearer token`). Register with `scripts/download_driams.py --site C --from-file <path>`, which verifies the
   SHA-256 against the pre-registered value and refuses a mismatch.
2. **Extract** `id`, `binned_6000` and the *E. coli* `raw` spectra only.
3. **Eligibility check, using only what the rule needs.** Apply the existing label rules
   (`labels.intermediate_as: resistant`, the pre-registered ambiguous and missing value lists) and count
   *Escherichia coli* × Ciprofloxacin rows by class. **Two thresholds, both fixed here:**
   - **(E1) Site eligibility**, the existing pre-registered rule: `pair_selection.min_per_class_external`
     = **≥ 30 per class** at an external site.
   - **(E2) Version 0.8 power precondition**, derived from E1 applied to the part that carries the result:
     the **held-out 30 % must contain ≥ 30 resistant and ≥ 30 susceptible** rows. With a 30 % held-out part
     this implies roughly ≥ 100 per class in eligible C.
4. **The rule is fixed and outcome-blind.** No AST outcome, model score, or any quantity computed from a
   model may be used to modify E1 or E2. Only class counts are inspected at this stage.
5. **Branches, decided now:**
   - **E1 and E2 pass** → proceed to 6.2.
   - **E1 passes, E2 fails** → **STOP the adaptation experiment.** C is too small to carry it. C may be
     reported as a further external test site in a dated Version 0.7 addendum (protocol amendment 3,
     point 4), and Version 0.8 returns for approval with a new plan. **Do not silently substitute
     DRIAMS-D.**
   - **E1 fails** → **STOP.** Report C's counts and that it is unusable for this pair. **Do not substitute
     another dataset.**
6. **C is built as a separate cohort**, never by rebuilding the primary dataset: same preprocessing settings,
   so it shares `feature_fingerprint` `347cbd6d5d956ff9` and has its own `row_fingerprint`. The primary
   dataset, its five splits, every saved model and every logged result stay untouched (protocol amendment 3,
   point 4).

Until E1 and E2 both pass, **nothing is fitted and nothing is scored.**

### 6.2 Partition — deterministic, and fixed before the data is seen

| | |
|---|---|
| Adaptation part | **70 %** of eligible C rows |
| Held-out part | **30 %** — the remainder |
| Seed | **42** |
| Unit | **whole patient groups** where C carries a patient identifier; otherwise each spectrum is its own group |
| Procedure | `grouped_subsample(meta_C, all_rows, round(0.70 · n), seed=42)` — the existing, tested function, which adds whole groups in a seeded permutation while the total stays within budget and **refuses a result below 99 % of the requested size**. The held-out part is exactly the complement. |

The procedure is deterministic given C's contents and seed 42, so it is reproducible and cannot be re-drawn
to taste. It is run **once**, before any label distribution in the parts is examined.

### 6.3 Leakage controls, enforced in code and not only documented

Every one of these aborts the run:

1. Adaptation ∩ held-out = **0 rows and 0 patient groups**.
2. Neither part intersects **any** Version 0.7 training, validation or test row (C is a separate cohort, so
   this should be vacuous; it is asserted because a vacuous assertion costs nothing and a wrong assumption
   costs everything).
3. The held-out part is listed in `evaluation.locked_test_splits` (or the equivalent guard) from the moment
   it is created **until** the single Version 0.8 scoring, so every script in the project refuses it —
   exactly as `temporal` and `external` were refused until Version 0.7.
4. No row of the held-out part appears in any existing test-log row.
5. The baseline model's training rows do not intersect either C part (vacuous for a separate cohort;
   asserted anyway).
6. The append-only log is hashed before and after; the run appends only, and records both hashes.

## 7. Baselines, and the order of comparison

All baselines and adapted models are scored on the **same** held-out rows, so every comparison is paired.

| # | Model | Saw any C row? | Role |
|---|---|---|---|
| B0 | prevalence — always predicts the C adaptation part's resistance rate | no | no-skill reference (protocol section 5); needs no fit |
| B1 | **the saved project model** `v0.4.0-tuned_lightgbm-random-seed42`, unchanged, with the carried-over Version 0.6 zone edge 0.1026 | **no** | **the primary baseline** |
| B2 | the Version 0.7 `external` refit (trained on A only, seed 42), with its own calibrator and the same carried-over edge | no | secondary baseline, so the comparison is not confounded by *which* A rows were used |
| A1 | **recalibration-only** — B1's frozen model with `(A, B)` and the edge refitted on C's adaptation part | adaptation only | **the primary adapted arm** |
| A2 | A + C refit — Version 0.4 setting, refitted on A-train + C-adaptation, own calibrator and edge | adaptation only | secondary adapted arm |

**Comparison order, fixed:**

1. **Primary:** A1 versus **B1** on the Brier score. One comparison.
2. **Co-primary:** A1's zone pair versus B1's zone pair, by the two conditions in section 3.
3. **Secondary, confirmatory:** A2 versus B1 on the Brier score, Holm-adjusted with the primary.
4. **Secondary, descriptive:** everything against B2 and B0; the guardrails of section 8.

## 8. Statistics

- **Effect measure:** paired difference on the same held-out rows, baseline minus adapted for Brier (so
  positive favours adaptation); adapted minus baseline for NPV and coverage (so positive favours adaptation).
- **Interval:** percentile bootstrap, **2,000 resamples of whole patient groups**, **seed 42**, 95 % level —
  the protocol's existing method (`summarize_bootstrap` with `reference=`), which resamples both models on
  the same draws.
- **Paired, not unpaired:** both models are scored on identical rows, so the paired interval applies. The
  second-level unpaired interval is used **only** if a comparison ever spans test sets that share no rows.
- **Repetitions / seeds:** A2 has random training, so seeds 42–46 with mean and range reported and intervals
  for seed 42 (protocol decision 6). A1 changes three parameters by deterministic convex optimisation, so it
  has one fit; this asymmetry is stated in the report rather than hidden.
- **Multiple comparisons:** the primary is a **single** pre-specified comparison and is not adjusted. The two
  confirmatory Brier comparisons (A1 vs B1, A2 vs B1) are additionally reported with **Holm adjustment across
  the two arms**, and a claim about A2 requires the adjusted interval. The learning curve, the B2 and B0
  comparisons and all secondary metrics are descriptive and are labelled as such; they never support a
  primary claim.
- **Secondary endpoints, reported always and separately from the primary:** AUROC (a **guardrail** — it
  cannot move for A1 by construction, and for A2 the paired interval must not exclude 0 in the unfavourable
  direction), PR-AUC beside the resistant share, calibration slope and intercept, Brier beside the prevalence
  Brier, and at the operating threshold sensitivity, specificity, balanced accuracy and the full confusion
  matrix.
- **Drift, reported in its own section and never described as performance** (the specification requires the
  distinction): the Version 0.7 feature-only diagnostic on C's inputs — per-bin standardised mean difference
  against the A training site, the lowest 20 bins separately, the same measure on the Version 0.6 regions —
  plus prediction- and confidence-distribution comparisons. No AST label is used, and it runs **after** the
  endpoints are logged.

## 9. Success and failure criteria

Fixed now, arithmetic, with nothing left to judge once the numbers exist.

**Adaptation is supported** if *both*:

- the paired 95 % interval of Δ Brier (B1 − A1) **excludes 0 with Δ > 0**; and
- the co-primary zone pair holds: `NPV_A1 ≥ 0.95` **and** `Coverage_A1 ≥ Coverage_B1 − 0.05`.

**Adaptation is not demonstrated to help** if the Δ Brier interval **includes 0**. Reported in exactly those
words — never as "no difference", never as "adaptation works", and never re-analysed to find a subgroup where
it does.

**Adaptation is harmful** if the interval **excludes 0 with Δ < 0**, or if `NPV_A1 < 0.95` while B1's
`NPV ≥ 0.95`.

**Mixed outcomes are possible and are reported as such**, for example a Brier improvement with a zone that
fails its coverage floor. That is a real and interpretable finding — better average probabilities bought by
refusing to answer — not a result to be resolved in favour of either side.

Given Version 0.7, **a null primary result is the expected outcome**, and it receives the same prominence as
a positive one.

## 11. Stop conditions — abort rather than adapt the methodology

The run aborts, and the failure is reported, if any of these holds:

1. C's archive SHA-256 does not match the pre-registered value.
2. **E1 fails** — C does not satisfy the existing pair-selection rule. Report counts; do not substitute
   another dataset.
3. **E2 fails** — the held-out part would carry fewer than 30 per class. Report; return for approval; do not
   substitute DRIAMS-D silently.
4. `grouped_subsample` refuses the 70 % budget (whole groups cannot fill it to 99 %), so the partition would
   not be the pre-registered one.
5. Any leakage assertion in 6.3 fails.
6. The baseline model fails its reproducibility gate.
7. The working tree is dirty at run time.
8. The append-only log changes in any way other than rows being appended.
9. C's feature fingerprint differs from `347cbd6d5d956ff9`, meaning it was built with other preprocessing and
   is not comparable.

In every case the correct action is to **stop and report**, never to adjust a threshold, a target, a
tolerance, an endpoint or the partition so that the run can continue.

## 12. What this protocol deliberately does not decide

- Whether DRIAMS-C is usable at all, and the size of the two parts in rows. Unknowable until the eligibility
  check runs; the counts will be reported either way.
- Whether fine-tuning the booster would help. Rejected here for lack of established methodology, recorded as
  future work.
- Whether the specification's `model_v1 / v2 / v3` versioning becomes a registry file or stays in the
  existing `amr-model-bundle/1` cards. An engineering choice with no bearing on the science; settled during
  implementation.
