## Why this pair

- **It was designated in Version 0.1.** `config.yaml` names ceftriaxone as `target.benchmark_antibiotic`, a
  "sanity-check pair reported next to the main pair". It was never modelled: until now it appears only in
  the Version 0.1 label counts.
- **It is the cheapest honest second pair.** Every ceftriaxone spectrum's raw file is already on disk, and
  6,396 of the primary dataset's 6,410 spectra carry a ceftriaxone result.
- **The question** is whether the project's method carries to a second antibiotic: the frozen
  preprocessing, the Version 0.4 LightGBM search and the protocol's threshold rule. Does it give a
  ceftriaxone predictor that beats chance on new patients and holds at other sites? How does it compare
  with the ciprofloxacin result on the same spectra, and does a second antibiotic need its own search?

## One fact against the pair, stated before anything is run

cohort:

| Susceptible at DRIAMS-A | ≥ 500 | 3,819 | met |

The Version 0.1 table (`results/metrics/eda/pair_candidates.csv`) lists ceftriaxone as eligible, with 1,086
resistant at DRIAMS-A, because it counted labels before the cohort rules existed. The Hospital Hygiene
exclusion, a locked design decision, removes 659 DRIAMS-A spectra, and **645 of them are
ceftriaxone-resistant**. That is the pattern of screening isolates, which is why they are excluded. For
ciprofloxacin the same exclusion still left 971 resistant in the built dataset, so the main pair was
unaffected.

**How it is handled.** Ceftriaxone was never chosen by this rule; it was designated as the benchmark. The rule
is not rewritten, and the shortfall is not explained away: every result must say that this pair does not meet
the project's own eligibility minimum on its cohort. The cost is precision:

## Cohort

- The builder processes every ceftriaxone candidate from its raw file with the frozen preprocessing. Each
  spectrum it shares with the primary dataset must come out **byte-identical** to that dataset's row; any
  difference stops Version 1.1 before anything is fitted.
- The splits are **derived** from the primary dataset, as the I-excluded dataset's were: every spectrum keeps
  its part, so no patient changes part, and a spectrum that is not in the primary dataset is in no split.
- **Left out of every split: 93 isolates with a ceftriaxone but no ciprofloxacin result, 27 of them
  resistant (29 %, against 10.2 % in the cohort)** — DRIAMS-A 36 (11 resistant), DRIAMS-D 57 (16). Another
  20 spectra fail the same processing checks as in the primary dataset (3 resistant), and 14 primary spectra
  have no ceftriaxone result.
- **Stated now:** the cohort is *isolates tested for both antibiotics*, not *all ceftriaxone-tested E. coli*.
  The left-out group is resistance-enriched, so a result on this cohort cannot be assumed to hold for it.
  This is accepted because it keeps the partition every earlier version used: no patient moves, and the
  ciprofloxacin comparison runs on the same spectra. Placing the 93 isolates would need new split code,
  whose own choices would then have to be pre-registered (decision 2 below).
- One intermediate result (DRIAMS-A) is counted as resistant. The I-excluded sensitivity analysis is not run,
  because it would change one spectrum.

## Method

**LightGBM only.** It won the Version 0.4 validation comparison of four families, and the Version 0.5
networks did not beat it. Searching the other families again would add hours and a multiple-comparison
problem with no question behind it (rule 14).

**Arm T (primary).** The locked Version 0.4 procedure (`docs/v0.4_search_plan.md`, "Procedure" and the
LightGBM row of "Search spaces"), unchanged except for the label: 5 patient-grouped stratified folds (seed
42) in the `random` training part; 30 random draws (seed 42) from the same space; the highest mean
cross-validated AUROC wins, ties to the first listed; Platt calibration on the out-of-fold predictions;
seeds 42–46, with seed 42 reported and saved; the threshold is set on the validation part. The search took
about 40 minutes on this laptop in Version 0.4.

**Arm F (secondary).** The Version 0.4 ciprofloxacin setting exactly as recorded in
`results/metrics/v0.4/ecoli_ciprofloxacin/best_model_card.json` → `params` (300 trees, learning rate 0.1,
31 leaves, minimum leaf 10, column share 0.3, row share 1.0, L2 10, no class weights). It is fitted on the
same training part with the same calibration and threshold rule, seed 42 only. It asks whether a second
antibiotic needs its own search, or whether the first one's setting carries over.

| Split | Scored once each | Question |
|---|---|---|
| `random` | T (seeds 42–46), F (seed 42) | primary endpoint; T against F |
| `temporal` | T's setting, refitted on the `temporal` training part | does it hold on later data? |
| `external` | T's setting, refitted on the `external` training part; B and D reported separately | does it hold at other sites? |

For `temporal` and `external` it is done exactly as Version 0.7 did for ciprofloxacin. The `random`-split
winning setting is carried unchanged, refitted on each split's own training part, calibrated the same way
and thresholded on that split's validation part. The refit on the `random` training part must reproduce
T's validation AUROC to 1e-9 before anything is scored.

**Not run:** `within_year` and the size-matched run. The patient-overlap check is not specific to the
antibiotic, it was answered for these spectra and this method in Version 0.4, and `within_year` validation
holds 21 resistant spectra. `external_ab` is also not run: it asked Version 0.7's two-site question, which
is about sites, not antibiotics.

## Endpoints, and what may be said (fixed now)

1. **Primary:** T (seed 42), `random` test AUROC with a 95 % patient-group bootstrap interval (2,000
   resamples, seed 42); PR-AUC co-primary, whose no-skill level is the test prevalence, 9.2 % (79 / 856).
   "Better than chance" may be said only if the AUROC interval's lower bound is above 0.5.
2. **The published reference.** `config.yaml` records AUROC 0.74 (Weis et al., 2022) for this pair at
   DRIAMS-A. Before any result is written, that figure is checked against the paper and quoted with its
   citation; if it cannot be confirmed, it is not quoted. The comparison is descriptive only (inside,
   above or below our interval). The cohort, split and exclusions differ, so "matches" or "beats" is never
   claimed.
3. **T against F:** paired AUROC difference on the `random` test part, paired bootstrap. An interval
   containing 0 means "no demonstrated difference", never "equivalent".
4. **Ceftriaxone against ciprofloxacin:** the `random` test part is the same 856 spectra for both. T's
   ceftriaxone AUROC minus the saved Version 0.4 model's ciprofloxacin AUROC, paired bootstrap over
   spectra. The ciprofloxacin side uses the **stored** Version 0.4 test probabilities and is not re-scored.
   They are used only after they cover exactly those rows and reproduce the logged AUROC and Brier score
   (amendment 2, point 3). This describes how hard the two labels are for one method; it is not a
   comparison of models.
5. **Generalisation gap:** `random` minus `temporal`, minus B and minus D, with intervals from independent
   bootstraps, as Version 0.7 computed them. An interval containing 0 means "no gap demonstrated", always
   stated with its width and never as "no gap". DRIAMS-B holds 45 resistant spectra, so no conclusion rests
   on B alone.
6. **Threshold-dependent metrics** (sensitivity, specificity, precision, NPV) are secondary. With 34
   resistant validation spectra, one spectrum moves validation sensitivity by 2.9 points, so the threshold
   is coarse, and it is reported as such.
7. **Version 1.1 is complete when it has been run and reported, whatever the result.** A null, a failure to
   beat chance or a large gap is a result (rule 11).
