# Version 0.4 search plan (fixed before any tuning run)

Written on 2026-09-17, before any Version 0.4 model was trained. It applies the approved
[evaluation protocol](evaluation_protocol.md) to Version 0.4 and does not change it. The exact settings
are in `config.yaml` → `tuning`.

## Goal

Improve on the Version 0.3 baselines systematically:
- hyperparameter tuning;
- class weights;
- feature selection, PCA and coarser bins;
- gradient boosting;
- probability calibration.

Then compare every model in one table: accuracy, precision, recall, F1, ROC-AUC, PR-AUC, training time
and inference time.

## Procedure (dataset `ecoli_ciprofloxacin`, `random` split)

1. **Folds.** The training part (2,977 samples) is divided into 5 patient-grouped, stratified folds
   (`StratifiedGroupKFold`, seed 42). The same folds are used for every model family.
2. **Search.** Every setting listed below is scored by 5-fold cross-validation inside the training part.
   The setting with the highest mean AUROC wins; ties go to the setting listed first. PR-AUC and fit time
   are recorded too. Validation and test data are not used.
3. **Final model per family.** The winning setting is trained on the whole training part.
   - Probabilities are calibrated with a sigmoid (Platt) fitted on the out-of-fold predictions of the
     same 5 folds, so calibration uses training data only.
   - Families whose training depends on the seed are trained with seeds 42–46. Seed 42 is reported and
     can be saved.
4. **Validation** is used only for:
   - the cut-off: the highest threshold with validation sensitivity ≥ 0.90, on calibrated probabilities;
   - choosing the saved Version 0.4 model: the family with the highest validation AUROC;
   - describing how much calibration changes the Brier score and calibration slope.
5. **Test** (only with `--evaluate-test`, each model once, logged):
   - every family's final model on the `random` test part;
   - the Version 0.3 saved model, re-scored on the same test part for a paired comparison. Its
     predictions come from its saved file, so its AUROC must equal the logged 0.726;
   - **patient-overlap check:** the chosen family's whole search, calibration and cut-off are repeated on
     the `within_year` training part and on a patient-grouped subsample of the `random` training part of
     the same size (1,284 samples, seed 42). Each is scored on its own test part.
     - Re-tuning keeps the check clean: the `random` training part contains `within_year` test samples,
       so reusing the settings found there would leak.
   - The `temporal` and `external` test parts stay locked until Version 0.7.

## Search spaces

| Family | Settings searched | Count |
|---|---|---|
| Logistic regression | **features**: all 6,000 bins; 1,000 coarser 18 Da bins (sum of 6 bins, no learning); PCA to 50 or 200 components; the 300 or 1,000 bins with the highest ANOVA F-score. **L2 penalty**: C = 10⁻⁴ … 10². **L1 penalty** (embedded feature selection, all or coarser bins): C = 0.01, 0.1, 1, 10. **Class weights**: none or balanced | 100 |
| Random forest | 500 trees; features per split: √p, log₂ p or 5 %; minimum leaf size 1, 3 or 10; class weights: none or balanced per tree | 18 |
| LightGBM | 30 random draws (seed 42) from: trees 100 / 300 / 600; learning rate 0.01 / 0.03 / 0.1; leaves 7 / 15 / 31; minimum leaf size 10 / 20 / 40; column share 0.1 / 0.3 / 1.0; row share 0.7 / 1.0; L2 penalty 0 / 1 / 10; class weights: none or balanced | 30 |
| SVM, RBF kernel | standardised features; C = 10⁻² … 10³; γ = 10⁻⁵, 10⁻⁴, 10⁻³ (around scikit-learn's default of 1/6,000 for standardised data); class weights: none or balanced | 36 |

The ranges follow the DRIAMS authors' grids (`amr_maldi_ml/models.py` in BorgwardtLab/maldi_amr), with
additions for class weights, feature reduction and regularisation.

**Deliberately not done:**
- **No oversampling or SMOTE.** SMOTE interpolates between spectra, which creates unrealistic spectra in
  6,000 dimensions, and 23 % resistant is not an extreme imbalance.
- **No undersampling.** It would discard real training spectra. Class weights give the same reweighting
  without losing or inventing data.
- **No LightGBM boosting types other than gbdt,** to keep the search within the time budget.
- **No neural networks.** They belong to Version 0.5.

## Reporting

- Every searched setting, with its cross-validation results (`search_<family>.csv`).
- Each family's final model: validation metrics before and after calibration, and test metrics with
  95 % intervals from patient-level resamples.
- Paired AUROC differences to the saved Version 0.4 model and to the Version 0.3 model.
- Seed variation, the patient-overlap check, and training and prediction times.
- Tables are generated from the saved reports; no number is typed by hand.
